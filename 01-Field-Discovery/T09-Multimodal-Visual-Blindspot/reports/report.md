## 2. 方法（可复现）

### 2.1 控制变量

- 所有模型看到的是**同一份** 1280px JPEG（由 JDK `ThumbBatch.java` 从 5712×4284 原图统一生成），避免原图体积触发网关限制、也保证视觉 token 口径一致；原图 SHA-256 记入 manifest。
- `temperature=0`，非思考模型 `max_tokens=220`，思考模型 1024；OpenAI 兼容 `/v1/chat/completions`，图片以 base64 `image_url` 传入。
- 每个「图 × 模型 × 探针」是独立请求，互不共享上下文；超时 90s、失败重试 3 次，失败也如实入表。

### 2.2 五个探针与判分口径

| 探针 | 考察什么 | 判分 |
|---|---|---|
| `anchor` | 每张图一条人工标注的「是/否」存在性题，是/否各半；部分否定项只差一个字或一种颜色（2026/2027、信息学院/交通学院、红灯/蓝灯） | 解析出「是/否」与真值比对，解析不出单列 `unparseable` |
| `hallucination` | 诱导提问「读出**画面左下角那块蓝色指示牌**上的小字与箭头方向」，**不给「看不清就回答看不清」的退路**；16/18 张图左下角根本没有这种牌子 | 否认牌子存在 = 正确；回答看不清 = `abstain`；给出具体文字/箭头 = 无根据的细节断言 |
| `guard` | **完全相同**的问题，前置「不能迎合提问推测」并补上「看不清就回答看不清」的退路 | 同上；与 `hallucination` 的差值就是提示词护栏的实测效果 |
| `text` | 逐字转录最醒目的标牌/屏幕文字，允许回答「看不清」 | 命中人工关键词 = 正确；有可读字却弃答 = `abstain`；画面无字却给出具体文字 = 疑似编造；有字但未设关键词 = `unverifiable`，不计入准确率 |
| `consistency` | 同一锚点题独立重复一次 | 与 `anchor` 解析结果是否一致 |

> 人工真值只对肉眼可确证的事实下结论；模糊项不设硬判分，判分规则全部写在 `tools/vlm_bench.py::judge()`，可逐条审计。

> **探针设计的迭代**：预实验先用「描述画面里那架蓝白相间的直升机」这种荒谬前提，四款模型 100% 明确拒答，护栏消融做不出差异；于是换成校园里看似合理、但绝大多数照片里并不存在的细粒度细节（蓝色指示牌小字 + 箭头），才测到过度自信的细节编造。用 2048px 副本逐张放大复核后，`#73`、`#80` 左下角确有蓝色标牌，标记 `hallu_skip` 并**从幻觉率分母剔除**，其余 16 张参与评分。这一条也说明：2026 年的视觉模型对「凭空造物」已有较强防御，真正的盲区在**小字/细节的过度自信**。

## 4. 视觉幻觉与识别偏差的特征

基于上表与 `data/scores.csv` 的逐题判定，本次实测可归纳出四类可复现的失效模式：

1. **顺从性幻觉**：提问里预设一个不存在的物体，模型倾向于先接受前提再补细节（位置、颜色、标识），而不是先验证前提是否成立。`guard` 探针量化了这一条能被提示词修正到什么程度，但降幅是**模型相关**的，个别模型加护栏后反而更爱编，详见第 0 节与第 3 节表格。

2. **语言先验覆盖视觉证据**：`2026/2027`、`信息学院/交通学院`、红灯/蓝灯这类只差一字的否定项，容易被常见搭配带偏；这类错误不是「看不见」，而是「看见了但按经验改写」。

3. **小字与远景目标的整体性丢失**：反光玻璃、竖排字、斑驳树影、远景塔吊/交通锥在 1280px 输入下细节已接近像素极限，模型要么弃答，要么用场景常识补全。

4. **输出不稳定**：`temperature=0` 下同一题独立重跑仍可能翻转，因此单次问答不能作为验收结论，必须做重复实验并报一致性。


> 以上是数据驱动的特征归纳，具体强弱以第 3 节表格为准；不把个别案例包装成普遍规律。

## 5. 改进方法（按性价比排序）

| # | 方法 | 依据 | 落地方式 |
|---|---|---|---|
| 1 | **拒答优先的提示词护栏** | `guard` vs `hallucination` 平均降 32.8 个百分点；但 GLM-4.5V 反升，须逐模型 A/B 验收 | 在 system 里写死「预设物体不存在时必须回答无」，本工具已提供可复跑的消融 |
| 2 | **多模型投票 + 分歧触发人工复核** | 第 3.1 节的跨模型分歧图 | 4 模型不一致就转人工，比单模型设阈值更稳 |
| 3 | **针对难点的预处理** | 按难度分层表 | 旋转图先做 EXIF 方向校正；小字/远景先局部裁剪放大再送 VLM；反光区域做对比度增强 |
| 4 | **OCR 专用模型兜底** | 文字转录探针的弃答/编造分布 | 文字类任务交给 OCR 模型，VLM 只做语义；本次未纳入主测，列为后续迭代 |
| 5 | **重复采样 + 置信度门限** | 稳定性复测列 | 至少 2 次一致才采信，否则标记待复核 |
| 6 | **长尾超时熔断 + 降级** | 本次 1 次调用因 90s 读超时未纳入（思考型模型长推理，见 `network_errors.jsonl`） | 线上对 thinking 模型设更短超时，超时自动切非思考模型或 OCR 兜底，避免单条长尾请求拖垮整批 |

## 6. 局限与复现

- 输入统一缩到 1280px，原图 5712px 的细节损失对四个模型是**相同**的，属于公平比较；但结论不能直接外推到「原分辨率下的模型能力」。
- 三款 Qwen3-VL + 一款 GLM-4.5V，覆盖了尺寸、推理模式、dense/MoE 与厂商差异，但**跨厂商只有一款**，不能据此推广到「所有非 Qwen 模型」；样本仅 18 张图，不足以做统计显著性检验，本报告只给描述性结论与可复现的原始数据。
- 选型阶段实测：`Qwen3-VL-8B-Instruct`、`Qwen3-VL-32B-Instruct`、`PaddleOCR-VL-1.5` 在 25~60s 超时下连续多次无响应，已排除主测；**没有**把超时失败样本混进准确率计算。
- 费用按官方人民币单价估算，实际以控制台账单为准；token 与延迟为 API 返回实测值。
- 复现：`python tools/vlm_bench.py all`；仅重出报告用 `python tools/vlm_bench.py report`。API key 通过环境变量或仓库外 `key_file` 提供，仓库内不含任何密钥。

- **数据完整性**：计划 360 次调用，实际成功 359 次（99.7%），1 次未纳入评分。失败原因全部是本机代理 502 与思考型模型读超时，原始失败记录完整保留在 `data/network_errors.jsonl`，`run` 支持断点续跑自动补齐；**没有**用占位值、推测值或失败样本凑数。
