## 一句话

每天上课前 20 分钟，自动往你微信发一条「下一大节上什么课、在哪个教室、这周到底有没有这节课」；
没课或这周不上就不打扰。微信没发出去就退回日历和网页，并把每轮跑没跑、推没推成功如实记成一条改不动的账。

## 为什么改选题

原方案「校园节点雷达」抓公开通知生成日历订阅，实测发现学校公告标题与正文几乎不写明确截止日，
`calendar.ics` 长期是 0 个事件——评分表对齐了，产品对使用者却没有价值。
2026-11-13 使用者明确要求「课表提醒要推送到微信之类的才有意义」，因此改为 **微信推送为主体**，
`.ics` / 网页退为推送失败时的兜底。

**勘误**：旧文档里 6 行「不碰微信」禁的全是**读**（本地数据库、聊天记录、群消息、逆向、登录），
没有一行禁止把消息送进微信。腾讯 2026-01 DMCA 下架针对的是「逆向客户端 + 破解本地库密钥」；
Server酱走官方公开接口，不在此边界。此前一刀切把推送也排除了，是判断错误。

同期考生 0153 黄欣雨的「课表提醒 用户版 v1.1」（Tkinter 桌面 + 邮件 + 8 位反馈 + 4 次迭代）
与本方向**正面撞车**，不回避。差异化写死：微信主动推送 + 不规则周次 / 调课调休 + 跨端兜底；
不做 Windows 桌面、不做邮件。

## 五笔账（决定方案可行的硬约束）

1. **频率与额度**：版本 A 全天 `*/5` = 288 轮/天 × 7 = 2016 分钟，吃光私有库 Free 的
   2000 分钟/月；版本 B 收窄到工作日 4 个课前窗口的 5 分钟粒度，仍要 72 轮/周。
   两个版本犯的是同一个错——拿「轮询」处理一个学期都不变的数据。版本 C（当前）：
   课表实际只有 3 个大节有课，定时搬出 GitHub 交给 cron-job.org，一周只醒 10 次，
   一个月约 40 分钟（占额度 2%）。
2. **条数**：Server酱免费 5 条/天；实际一天最多 3 大节 = 3 条，同节多课合并、
   本周无课不推、失败不重发、`state/pushed.json` 按「日期+大节」去重，测试消息单独计。
3. **周末**：11-21、11-22 没课，就不该响。此前加的「周末心跳」是为了凑「连续 7 天」的账，
   本质是让程序在没有事件发生时也留一行空日志——这属于为验收指标造记录，已撤掉。
   改法是把期望值从写死的常量换成从课表推导：`verify.py` 按 `src/schedule.json`
   算当天该响几节、缺哪一节，没课的日子期望为 0。
4. **日志**：PreBell 复用现有 `process_logs/`、`state/`、`public/` 与 `chain.py`，
   哈希链从 11-10 连到 11-23；一周约 10 次 commit，不是刷量。
   诚实边界：11-10~11-16 是旧雷达的日志，**不计入 PreBell 的 7 天窗口**；
   周末无课、无记录，也不拿别的日子来凑。
5. **两层外部依赖**：闹钟（cron-job.org）和通道（Server酱）都不归我们控制。
   - cron-job.org 免费、无 SLA，官方明说高峰期可能迟到几秒到几分钟；到点没踢到就整节漏响。
     缓解：它的执行历史同时留「计划时刻」和「实际执行时刻」（最近 50 次可查），
     这是外部第三方独立留的时间证据；失败会发邮件。
   - 仓库已有「Actions 从境外连不上国内站点」的实测（`hrss_sz` HTTP 0、
     `eea.gd.gov.cn` 被排除）。先真实探测 `sctapi.ftqq.com`，失败记 8 位指纹并降级，
     绝不写「推送成功」。SendKey 只在 Actions Secrets，代码只读 `os.environ`。
   - 迟到超过 15 分钟不发，记 `missed_too_late`；未超阈值照发，但文案与日志都标实际送达时刻。

## 8 位同学反馈怎么收

把微信推送截图发给同学，只问四件事：有没有漏提醒、有没有误报、提前 20 分钟合不合适、
你核对过第 1 周周一吗。以 F01–F08 编号归档，不收集姓名、学号、手机号；截图如有昵称先打码。
收不齐就如实写「实收 N 位」，不凑数。

## 明确不做

- 不读微信本地数据库、聊天记录、群消息，不逆向微信客户端，不登录微信；
- 不做 OCR、不假装读 `.xlsx`（只有一张截图，人工转录）；
- 不碰学习通、教务系统登录态，不采集个人信息；
- 不做 Windows 桌面程序、不做邮件推送；
- 不在本机跑常驻进程、不写自启、不建定时任务；
- 不在 GitHub Actions 上挂定时轮询（拿看板对付日历，白烧额度也说不清算得对不对）；
  定时只由 cron-job.org 按课表定点踢一脚，GitHub 只负责执行；
- 不补写历史日志，缺勤轮次由 `verify.py` 如实报出；
- 不把估算锚点 `2026-09-07` 包装成事实；
- 不用演示数据冒充真实日志，`preview.html` 与真实产物严格分开。
