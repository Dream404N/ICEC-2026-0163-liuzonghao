# 006 · 把「用不了」定位到微信端绑定，并撤回一条错误结论

时间：2026-11-14 深夜

## 使用者的反馈

「我根本不理解你这个到底要怎么推送上课提醒给我，我现在根本就用不了」。

前几版写了大量架构、cron、哈希链、验真文档，但使用者仍然答不出三个问题：
消息从哪来、去微信的哪里看、自己到底要做什么。文档越厚越像黑盒，
判定为**交付方式失败**，不是功能缺失。

## 实际动作

1. 云端手工触发一次 `prebell-remind`（`preview_date=2026-11-16`），
   run `43613054508` 成功；作业日志读到 `status=ok / HTTP 200 / 3026ms / courses=3`。
   这条消息是让本人当场核验微信是否真的弹出，不计入自动运行日志。
2. 核查 GitHub 侧：`prebell-remind` 状态 `active`、默认分支 `main`、4 条 cron 都在；
   `prebell-daily` 只写汇总不推消息；旧雷达 `probe.yml` 的 `schedule` 仍是注释停用。
   没有第二个会推消息的任务。
3. **勘误**：此前 README / docs 写「`code:0` 真发到微信」。错。
   `code:0` 只证明 Server酱服务端受理了请求；微信能否弹出，取决于本人是否在
   `sct.ftqq.com` 关注「方糖」服务号并完成消息通道绑定。云端日志不能替本人确认送达。
   `004` 里其实已写过「微信是否收到仍需本人确认」，但被 README 的乐观措辞盖过去了。
4. 网页首屏改造（改 `planner.py` 模板后重跑生成，不是手改产物）：
   - 「今天」改为「今天 / 下一次上课」：周末或没课日直接列出下一个上课日的课，不再是空白页；
   - 新增「下一次微信提醒：X月X日 周X 08:20」，让「什么时候会响」当场可见；
   - 新增大白话三步卡片：绑定方糖 → 四个时刻自动发 → 去微信「方糖」会话看；
   - 日历卡片改口径：微信是增强层，手机本地日历才是最稳的一层。
5. `README.md` 的「你要做的事」从「就这两件」改为：1 件必须本人动手（微信绑定）
   + 2 件建议（核对课表、锚点周次）。

- 没有替使用者确认微信收到 —— 这一步只能他本人看手机。
- 没有补写任何自动运行日志，手工预览仍然不进 `process_logs/`。
- 没有新增定时任务、没有新增第三方通道、没有改动课表数据。
