# 008 · 需求变更：从「零常驻」改成「开机自启 + 日志自动提交」

日期：2026-11-15 下午。触发：使用者连续三问 ——

1. 「你确定安卓能够通知消息吗，不存在后台进程的情况下？」
2. 「Windows 直接帮我做一个安装包吧，一个可以开机自启动的程序，到了时间就会提醒上课的」
3. 「日志的话你也要每天自动化帮我 commit 到 GitHub，逻辑写到软件里面；还有就是要能即时测试软件通知」

## 被推翻的旧口径

`007-叮叮课表多终端本地版.md` 与 `tools/dingding/README.md` 上午版写的是
「不常驻、不自启、不跑定时任务、不产生运行日志、不会自动 commit」，
理由是怕后台与联网变成负担。这套口径**只对系统日历那一层成立**，
对「App 自己弹通知」并不成立：上午版 APK 的 `notify()` 只在 WebView 前台被调用，
划掉 App 就不会弹。使用者质疑得对，这里如实勘误。

## 改成什么

| 端 | 旧 | 新 |
|---|---|---|
| 安卓 | 只有系统日历 + 前台通知 | 系统日历 **+ AlarmManager 系统闹钟**（`RemindReceiver`，BOOT_COMPLETED 重排），无本 App 后台进程 |
| Windows | 只有 HTML + ics | 开机自启常驻程序 `--daemon`，每 15 秒查表、到点 `MessageBoxW` 置顶弹窗；`.ics` 保留为无进程兜底 |
| 日志 | 不产生 | `usage_logs/YYYY-MM-DD.jsonl` 只记真实事件，每天 23:50 由软件调 `commit_usage_logs.py` 自动推 GitHub |
| 测试 | 无 | Windows `--test` / 桌面入口；安卓「立即测试通知」「测试 10 秒后闹钟」 |

## 守住的三条底线

- **不伪造证据**：客户端日志放 `tools/dingding/usage_logs/`，与云端自动化运行日志
  `process_logs/` 完全分开，提交信息里写明「本机真实事件，非云端运行日志」；
  关机、断网、没启动那天不补写。
- **密钥不进软件**：`commit_usage_logs.py` 只读工作区外 `.workbuddy/.gh_token`，
  提交前扫描疑似密钥串；APK 依旧没有 INTERNET 权限，手机里不放任何凭据。
- **不冒充验证**：真机安装、退出 App 后闹钟是否真弹、Windows 常驻到点是否真弹窗，
  都还没做，文档里逐条列在「尚未验证」。

## 环境限制（如实）

本机安全策略禁用了 `schtasks.exe`，也没能生成 `.exe` 安装包，
因此 Windows 的安装动作由双击 `安装.cmd` 完成，**不是 Windows Installer 包**。
这一条写进了 `tools/dingding/README.md`，不隐藏。
