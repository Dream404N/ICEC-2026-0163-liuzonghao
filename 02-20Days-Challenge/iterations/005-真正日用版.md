# 迭代 #5：从「能跑通」改成「真能日用」

- 触发：2026-11-14 23:17，使用者原话
  「**你要弄一个我完全可以真正日用的课表软件 不然都不知道你在搞什么玩意**」。
  前一句是「可是你给我的软件方案真的是没办法用啊」。
- 性质：由**使用者真实反馈**触发的方案迭代，不是由运行日志触发的调参迭代。
  与 `iterations/prebell/README.md` 里约定的 011–013（日志驱动）互不冲突，不拿来凑那三次。

## 为什么说是「没办法用」（可核查的事实）

1. 远端 `actions/runs` 最近 8 次全是已废弃的 `campus-radar-probe`；
   新写的 `prebell-remind` / `prebell-daily` **零次运行**。
2. Secrets 只有 `PREBELL_SENDKEY` 一个；2.0 版要求的 `PREBELL_WXPUSHER_SPT` 从未填过。
3. 最要命的一条：`src/prebell/planner.py` 生成的 360 条 `schedule.json` 里
   **`course` 全部是 `null`**。它只按 `has_class_days`（星期几）机械排时点，
   完全不判断周次、不带课程名。消息模板是「课程（课表未核对）」。
   一个准时响、却不知道今天上什么课、也不知道这周有没有课的闹钟，不是产品。
4. 使用者要让它响，需要：注册 cron-job.org、造 PAT、建 6 个 job、装 WxPusher App、
   扫码拿 SPT、填 2 个 Secret、手动停旧 workflow。任何一步没做都静默失效。
5. 旧雷达 `probe.yml` 的 `schedule: '17 */3 * * *'` 还在跑，持续往 `process_logs/`
   写废弃程序的数据，污染新程序的溯源。

## 根因（自我勘误）

把官网评分点当成了产品规格：为了「7 天日志 / 3 次迭代 / 8 位反馈」，
一层层加静态表、外部闹钟、主备双通道、哈希链，每加一层就多一份使用者要手工配的东西。
11-14 白天还连改三次方向（Server酱 → 企业微信群机器人 → Server酱 + WxPusher），
每版手册刚交出去就作废。**问题不在使用者看不懂，在于交付物本身不可用。**

另外勘误 11-14 15:36 那轮回答里的行动建议「今晚把大纲落成代码」：
代码 15:53 就已落地（22 文件，`ead8323`），缺的从来不是代码，是让它真的响一次。
