# 数据驱动的 Git 迭代（不预写）

官网 L375 ② 要求「**基于日志**的至少 3 次 Git 迭代 Diff 记录」（20 分），
L440 会追问「异常数据原因及排障细节」。

**因此 011.md / 012.md / 013.md 不在此预写。**
必须等 `process_logs/` 里出现真实观察后，按下面格式创建，并与一次真实 commit 一一对应。

## 每份迭代记录应包含

| 项 | 内容 |
|---|---|
| 日期 | 真实日期 |
| 观察到的日志 | 引用具体 `process_logs/YYYY-MM-DD.jsonl` 的 `seq`、`key`、`result`、`error`、`latency_ms` |
| 异常描述 | 例如：某次 `skipped_late` 是 cron 排队还是 Actions 启动慢；某次 `error` 的脱敏指纹 |
| 采样边界 | 这次观察覆盖哪几天、哪些节次；哪些情况没覆盖（面试高追问点） |
| 改动 | 改了哪个文件、哪个函数，为什么这样改 |
| commit | 对应远端 commit SHA |
| 验证 | 改后 `verify.py` 的结果 |

## 建议节奏（见 RUNBOOK 第 6 节）

- 011：11/18，基于 11/16–17 首两日日志
- 012：11/20，基于 11/19 日志
- 013：11/22，基于 11/21 日志

三次都必须由前 1–2 天的真实日志驱动，**先有观察、后有改动**，顺序不能反过来。
若某天没有出现异常，就如实写「本窗口无异常，未改动」，不得编造问题来凑次数。

> 仓库既有 `iterations/001–004.md` 是改选题前的真实过程记录，原样保留、不删除、不回填。
