## 二、SendKey 怎么进去的（没有走网页表单）

本机 `pip` 连不上 pypi（连清华镜像也拿不到），装不了 `pynacl`；系统里也没有 libsodium。
写 GitHub Actions Secret 需要 libsodium 的 sealed box（`crypto_box_seal`），
所以用纯标准库实现了一遍：X25519 + HSalsa20 派生共享密钥 + XSalsa20-Poly1305，
nonce 取 `BLAKE2b-24(临时公钥 ‖ 仓库公钥)`。

这不是「自己发明密码学」，是把 nacl 的公开构造照着实现，并用**已知答案**验证过：

- X25519 对 RFC 7748 §5.2 测试向量（`a546e36b…` → `c3da5537…`）✅
- Salsa20 零输入首块前 8 字节 `9a97f65b9b4c721b` ✅
- Poly1305 对 RFC 8439 §2.5.2 向量（`a8061dc1305136c6…`）✅
- 篡改密文必须被拒 ✅

最终判定标准不是自测，而是**端到端**：密钥经过 GitHub 加密落库、Actions 取出、
真的发到微信上、返回 `biz_code=0`。这一步过了，才说明加解密是对的。

明文密钥从未写入任何仓库文件，只作为一次性环境变量进入两条命令；
上述验证脚本也放在仓库外的临时目录。

## 三、顺带发现两个真问题

### 1）文档里的分支名是错的

`PREBELL.md` 和 `resolve.py` 生成的 `cron-hints.txt` 里，触发 body 写的是
`{"ref":"master",...}`。但仓库默认分支是 **`main`**（本地 git 是 `master`，两边不一致）。
照文档建 job，cron-job.org 每次都会收到 **422 `No ref found for: master`**，
而且因为是第三方调用，报错不会出现在仓库里——**静默失败，一节都不会提醒**。

已改为 `main`，并在三份产物（`PREBELL.md`、`out/cron-hints.txt`、`schedule.md`）里同步。
这是「文档与真实环境不符」，只能靠真跑一次才发现。

### 2）验真会假报通过（更严重）

旧 `verify.py` 对每个应响的大节，只检查「日志里有没有 `schedule_slot` 这条记录」。
于是下面这些情况全部会被算成「齐」：

- `push.status=failed`：推了，但微信没收到；
- `reason=missed_too_late`：闹钟晚到超过 15 分钟，主动放弃；
- `reason=channel_failed`：渠道被判定不可用，直接跳过；
- `reason=throttled`：当日额度用尽。

也就是说：**它记录下了失败，却把失败判成了通过**。在评分点「任何人 clone 下来一键验真」
这个语境里，这比没有验真更糟——它是假证据。

改法：期望值仍从 `schedule.json` 取，但同时算两个集合——
`got`（有记录的大节）与 `ok`（`push.status == "ok"` 的大节）。
差额单独报一行 `响了但没推成功`，并附原因，退出码仍为 1。

实测三种情形：

```
齐 | 未推成功 P4(missed_too_late)          → 1/2，退出码 1
该响没响 2026-11-17-P3, -P4                → 缺一节也点名
推送了课表里没有的 2026-11-17-P1            → 反向也能抓
```
