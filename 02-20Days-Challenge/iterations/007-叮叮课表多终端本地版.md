# 007 · 叮叮课表：多终端、纯本地、不依赖微信

时间：2026-11-15 下午

## 触发

使用者连着提了三条要求：
1. 「先帮我做一个多终端提醒的课表，例如说安卓 APK、Windows 的」
2. 「跑本地部署就行了」
3. 「名字叫做叮叮课表」

背景是 11-14 深夜那条反馈：「我根本不理解你这个到底要怎么推送上课提醒给我，我现在根本就用不了」。
微信链路即使配置齐全，对使用者仍是个看不见摸不着的黑盒 —— 他手上没有任何一个能双击、
能安装、能自己确认的东西。所以这一版不再解释云端，**直接把软件交到他手里**。

## 架构判断（为什么不常驻）

「多终端提醒」最容易写成：每个端跑一个后台服务轮询云端。这正是被否掉的路线：
本机常驻、自启、定时任务都不是使用者要的，也和他此前的明确要求冲突。

改为：**提醒交给各终端自己的系统日历**。
课表一次写进 Windows 日历 / 安卓日历，每节课附一条「提前 20 分钟」的 VALARM / Reminders 记录，
由操作系统负责弹出。App 不需要常驻、不需要开机自启、不需要网络，关机重启和清后台都不影响。
应用或网页**开着时**到点额外弹一次，只是增强，不作为兜底。

## 新增内容

- `tools/dingding/build_assets.py`：从 `schedule.json` 的 140 条真实课程生成三端产物，
  唯一数据源，改课表重跑即可，不手抄任何一格。
- `tools/dingding/templates/app.html`：**一份界面模板同时给 Windows 和安卓用**，
  运行时靠 `window.DingDing` 是否存在自动切换模式；ES5 写法兼容老 WebView。
  首屏直出「今天 / 下一次上课」「下一次提醒：X月X日 周X 08:20（还有 X 小时 X 分）」。
- `tools/dingding/windows/叮叮课表.html` + `叮叮课表.ics`：双击即用，ics 导入系统日历。
- `tools/dingding/android/MainActivity.java`：WebView + 三个 JS Bridge 方法
  （`writeCalendar` / `notify` / `saveIcs`）。写日历带去重，重复点不会产生重复项。
  **Manifest 刻意不申请 INTERNET**，装完完全离线。
- `tools/dingding/build_apk.py`：**本机构建**，aapt2 → javac --release 8 → d8 → zipalign → apksigner，
  不需要 Gradle、不需要下载依赖、不需要 GitHub Actions、不需要网络。
  复用仓库里已有的固定开发签名，保证以后能直接覆盖安装。
- `dist/叮叮课表.apk`：24.5 KB，本机实测产出。
- `.gitignore` 增加 `tools/dingding/build/`，中间产物不入库，成品 APK 入库。

## 实测结果（本机，不冒充真机）

- `apksigner verify` 通过，证书 SHA-256 `488fb014…8cfa`，与 PowerProbe v1.5.0 起固定签名一致。
- `aapt dump badging`：包名 `com.icec.dingding`、label「叮叮课表」、minSdk 26、targetSdk 29。
- APK 内 `AndroidManifest.xml` / `classes.dex` / `resources.arsc` / `assets/index.html` 齐全，
  内嵌课表 **140 条**；DEX 里确认有 `MainActivity$Bridge` 及三个方法。
- 权限只有 `READ_CALENDAR` / `WRITE_CALENDAR` / `WRITE_EXTERNAL_STORAGE(maxSdk28)`，
  **确认没有 INTERNET**。
- 网页 JS 用 `node --check` 通过；`build_assets.py` 的断言（非空课程名、键唯一）通过。

## 没做 / 不冒充

- **没有真机安装测试**，也没有实测「写入手机日历」是否弹提醒 —— 这一步要真人装一次才能确认。
- 没有新增任何 GitHub Actions workflow，没有新增云端服务，没有发布到公网。
- Windows 版是单个 HTML（双击用浏览器打开），不是 `.exe`，没有做安装器。
- 课表第 1 周周一仍按 `2026-09-07` 估算、未与校历核对；教师姓名不展示。这两个如实边界沿用 PreBell。
- 没有改动 PreBell 的微信链路与 4 条 cron，两套并存：微信是增强，本地日历是兜底。
