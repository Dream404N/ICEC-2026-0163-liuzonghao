## 改了什么

| # | 改动 | 理由 |
|---|---|---|
| 1 | cron `*/30 * * * *` → `17 */3 * * *` | 每 3 小时 8 轮；放在第 17 分钟避开整点排队高峰，减少缺勤与限流 |
| 2 | 新增 `src/interests.json`，`relevance()` 先判排除词再判关注词 | 公示 / 结果 / 拟聘 / 新闻类不进日历和主列表，只统计「已过滤 N 条」 |
| 3 | 日志 `planned_minute` → `slot_3h` | 降频后不再假装知道精确计划时刻，改记本轮所属的 3 小时时段 |
| 4 | 每日 Merkle root 改为**每轮滚动重算** | 原设计只在 23:30 后触发；改成每 3 小时后，最后一轮是 UTC 23:17 / 北京 07:17，条件永远不成立。滚动重算不受时区与 cron 延迟影响，当天最后一轮即日终锚 |
| 5 | `verify.py` 期望轮次 48 → 8；心跳格 48 → 8；全仓文案 336 → 56 | 口径一致，避免文档与日志自相矛盾 |
| 6 | 同步脚本加 `PROTECT_PREFIXES` | 云端生成的 `process_logs/`、`state/`、`public/` 本地不保存；原同步逻辑会把「远端有、本地没有」的文件删掉，下一次同步就会毁掉证据链 |
| 7 | PLAN / README / 样张补「只做三件事」 | 学习通、微信、课表、断网提醒这些扩展项明确不做，不铺大摊子 |
