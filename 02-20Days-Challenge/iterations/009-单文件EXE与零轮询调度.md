# 迭代 009 · 单文件 EXE 与零轮询调度

**触发反馈（2026-11-15 傍晚，原话）**：
「你编译一个多功能的EXE给我啊 / 要能自己调节什么的 / 每15秒检测课表是什么鬼啊 病毒吗」

## 判断：使用者是对的，我上一版做错了两件事

1. **每 15 秒 `while True` 全表扫描**是典型的忙等。140 条课表、一天 5760 次重复比对，
   既没有必要，也确实会让人怀疑进程在后台干什么。这不是「为了不漏提醒」的必要设计，
   而是把「到点触发」偷懒写成了「不停检查」。**已删除，不是解释过去了事。**
2. **交付形态不对**：上午给的是 HTML + `.ics`，下午给的是 `.cmd` 安装器 + Python 脚本，
   都不是使用者要的「一个能自己调节的 EXE」。这一次给真正的单文件可执行程序。

## 这次实际改了什么

| 项 | 之前（008） | 现在（009） |
|---|---|---|
| 调度 | `while True: sleep(15)` 每分钟 4 次扫 140 条 | 启动时读一次课表 → 单次 `threading.Timer` 睡到下一个事件 → 到点再算下一次 |
| 休眠/改时间 | 靠 15 秒轮询自然覆盖 | 最多每 30 分钟一次**校准唤醒**，只重算内存时间点，不弹窗/不写日志/无 I/O |
| 轮询次数 | 无限 | 界面实时显示「轮询 0 次 ｜ 到点唤醒 N ｜ 校准 M」 |
| 主程序 | `dingding_win.py --daemon`（pythonw） | `dist/叮叮课表.exe`（PyInstaller `--onefile --noconsole`，11.0 MB） |
| 设置 | 改源码 / 改 config.json | 图形面板：提前分钟数、总开关、声音、弹窗、开机自启、静音时段、只在工作日、日志提交时间、自定义课表文件 |
| 测试通知 | 命令行 | GUI 内即时按钮 + `--test` 命令行 + 桌面入口 |
| 冷启动 | 秒开 | 单文件 EXE 约 5–7 秒（解压运行时），**如实写明** |

`dingding_win.py` 的 `daemon()` 也同步改成同一套事件驱动，仓库里不再留任何
`time.sleep(15)`；它降级为命令行后备工具，仅为兼容旧自启项保留。

## 口径作废与边界

- **008 的「每 15 秒查表」作废**，007 的「零常驻」早在 008 已作废；以 `tools/dingding/README.md` 为准。
- EXE 是 **PyInstaller 单文件 Python 程序**，不是原生 C++、不是 `.msi` 安装包；
  开机自启仍要本人双击 `安装.cmd` 才写注册表，程序不擅自写自启。
- Windows 弹窗层仍依赖进程存在；`.ics` 导入系统日历是唯一不依赖进程的一层。
- 单文件 EXE 冷启动 5–7 秒，是 `--onefile` 解压代价，不掩饰；GUI 已启动后按钮是即时的。
- 真机装 APK、退出 App 后闹钟、Windows 到上课时刻真弹窗，仍需真人验证，未冒充已测。
