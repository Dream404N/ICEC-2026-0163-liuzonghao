### 01 · APK 签名漂移与 commit 规则

- **使用者原话**：「还有就是你是不是每次生成APK的签名都不一样 然后我强制安装上去之后发现之前的日志好像没了」。
- **排查结论**：使用者判断正确。解析 APK v2 签名块取证，三次历史构建的证书指纹互不相同
  （截图表格可见 `11/08 14:46 → 22507BE4FF5DBE588804584B`、`11/08 15:18 → C0A8948013D3E2E5B2B42FFD`
  等前 24 位）。每次 CI 换签名 → 只能卸载重装 → 应用私有数据被清。
- **后续修复**：v1.5.0 起固定 `tools/PowerProbe/signing/powerprobe.jks`
  （证书 SHA-256 `48:8F:B0:14:…:8C:FA`）；采样点与日志即采即写，并镜像到公共
  `Download/PowerProbe/`，卸载不删；重装后主界面自动读回上次日志。
- **同批确立的长期规则**：每次任务收尾直接 commit 到 GitHub 并回报远端 SHA。
  截图里对应远端 `570b75d`（9 个文件变更）、本地镜像 `df54fd0`。

### 02 · 应用选择器的搜索改造

- **使用者原话**：「你这个APP还得完善一下 就是选择测试应用的页面没办法直接搜索
  我希望是KSU那种搜索选择的 你这种太难用了」；另有「还有你之前修改的发行版commit到GitHub了吗」。
- **结果**：新页面交互预览 —— 搜索框可按应用名 / 包名过滤（截图示例 `phi`、`com.tencent`），
  默认推荐 Phigros，点按选中、长按复制包名，带「显示系统应用」开关。
  KernelSU 只参考视觉与交互，代码自实现（GPL-3.0 边界），依赖用 Apache-2.0 的 Material Components。
- **证据**：截图里「改动已全部落到远端（`20bab38c`，63 个文件 0 差异），CI 成功」。
- 相关目录：`tools/PowerProbe/`、`01-Field-Discovery/T02-Phone-Power-Thermal/`。

### 03 · 无后台通知的质疑与需求变更

- **使用者原话**（截图可见时间戳 `14:00`，共四点）：「你确定安卓能够通知消息吗
  不存在后台进程的情况下？」；「windows的你直接帮我做一个安装包吧 一个可以开机自启动的程序
  到了时间就会提醒上课的」；「日志的话 你也要每天自动化帮我commit到GitHub 逻辑写到软件里面」；
  「还有就是要能即使测试软件通知」。
- **公开认错**：上午版「没有后台进程就通知」其实做不到 ——「交给系统日历」只对日历那层成立，
  APK 自己的 `notify()` 只在 App 开着时被网页调用，划掉后台就不弹。不是嘴上解释，
  改 v1.1.0 用 `AlarmManager` 系统闹钟 + `BOOT_COMPLETED` 重排，并保留系统日历兜底。
- **同一条反馈的后续演进**：使用者之后又指出「每15秒检测课表是什么鬼啊 病毒吗」，
  于是删掉忙等轮询、改单次 Timer 事件驱动，并编译出带设置面板的单文件 EXE。
  见 `02-20Days-Challenge/iterations/008-开机自启多终端与客户端日志自动提交.md`
  与 `009-单文件EXE与零轮询调度.md`（远端 `3200f69` / `5ba27e0`）。
